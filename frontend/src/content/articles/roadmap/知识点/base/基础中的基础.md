### reactive / ref
数组 ref, 对象一般 reactive
why reactive 不能 [], 因为**不能直接整体重新赋值**

| 特性       | `ref`                                                | `reactive`                                                                   |
| :------- | :--------------------------------------------------- | :--------------------------------------------------------------------------- |
| **适用类型** | 原始值 (number, string, boolean) 和 对象                   | **仅对象** (包括数组、Map、Set 等复杂类型) <br>why？因为底层return new Proxy...，Proxy 只能代理上面的内容 |
| **访问方式** | `.value` 访问/修改值                                      | 直接访问/修改属性                                                                    |
| **底层实现** | 包装成一个带有 `.value` 属性的**对象**，用 `Proxy` 拦截 `.value` 的读写 | 直接用 `Proxy` 包装目标对象本身                                                         |
| **解构问题** | 解构会失去响应性                                             | 解构会失去响应性 (`...` 扩展运算符也会)                                                     |
| **内部转换** | `reactive` 内部如果遇到 `ref`，会自动解包 (unwrap)               |                                                                              |
- reactive/ref的目的是让被定义变量本身活起来，而不是监听变量内部属性是否有变化来变化。比如 const profile = reactive({ name: accountStore.accountName })，它只在初始化时读取一次 store。解构失去响应性
	```bash
	reactive 的响应性来自 Proxy。
	
	直接访问 state.name：
	会走 Proxy get，所以有响应性。
	
	解构 const { name } = state：
	只是在那一刻复制了 state.name 的值。
	
	后面访问 name：
	访问的是普通变量，不再走 Proxy get。
	
	所以：
	不会 track，不会收集依赖，也就不会响应式更新。
	```

### defineModel
你的疑问很关键，这里确实容易搞混。先直接说答案：

```js
const startDate = defineModel('startDate', { default: '' });
// 这一行是完全正确的，且等同于 emit('update:startDate', innerStart.value)
startDate.value = innerStart.value;
```

**用 `defineModel` 时，直接赋值就是合法的，它就是触发 `emit` 的语法糖。**
`defineModel` 是 Vue 3.4+ 引入的编译宏。它在编译后会生成：

1. 一个 **props** 叫 `startDate`
    
2. 一个 **emit** 事件叫 `update:startDate`
    
3. 一个 **ref**（就是你拿到的 `startDate`）

### composables 组合式函数(放局部状态，如果是全局状态)

- 不同于 mixin，composables是**有状态逻辑**：不只是单纯工具函数，函数内部会保存数据（状态）
	- mixin如果不包工厂函数：所有组件在传参的状态下共用 mixin 内部同一个引用类型数据，造成状态污染。( 提示！mixin 本身的结构也是状态独立的，和 composables 一样有独立的 ref/reactive... )
- 不同于工具函数 utils，无状态，输入→输出
- 组合式函数：**自带状态、可以监听、可以绑定生命周期**。（两种方式👇)
	- 1. 如果你把 ref/reactive/computed/watch/onMounted 状态写在函数中 --> 就能隔离状态，每次调用独立。✅
	- 2. 状态提升到函数外部 → 全局单例，调用全部共享（❌不推荐，类似简易版 pinia）

### 宏任务 / 微任务与这一区别的关系

| 概念   | 典型代表                              | 任务存储位置             | 是否阻止 GC            |
| ---- | --------------------------------- | ------------------ | ------------------ |
| 宏任务  | `setTimeout` `setInterval` I/O    | 浏览器定时器线程 / 事件队列    | ✅ 会阻止，直到任务被执行或取消   |

### axios 拦截器
- axios.js 的错误拦截问题 -- 就是其实还是要向下抛出错误的，不然下层的错误就接不到

**简单理解：** Axios 拦截器也是 Promise 链。错误拦截后如果不继续抛出，下层的 `catch` 就接不到错误。

```js
axios.interceptors.response.use(
  response => response,
  error => {
    return Promise.reject(error)
    // 或者：throw error
  },
)
```

如果错误回调什么都不返回，相当于返回 `undefined`，Promise 会从失败状态变成成功状态。

### `typeof` vs `instanceof`

> 核心区分：
> 
> **`typeof`：看基础数据类型（原始类型）**
> 
> **`instanceof`：看实例属于哪个构造函数 / 类（只用于对象、类实例）**

**简单理解：** `typeof` 判断值的大类型；`instanceof` 判断对象是否在某个构造函数的原型链上。

```js
typeof 'hello'      // 'string'
typeof null         // 'object'，特殊情况
typeof []           // 'object'
[] instanceof Array // true
```

- 判断数组优先用 `Array.isArray(value)`。
- 判断 `null` 用 `value === null`。

### Object 本身的方法，如 getOwnPropertyName, 等的使用场景是什么？为什么要用？和原型链的关系是什么？
**原文观察：** JavaScript 中实际的方法名是复数形式 `Object.getOwnPropertyNames()`。上面“读不到”的情况通常不是属性不存在，而是要读取的属性位于原型链上；`Object.keys()` 和 `Object.getOwnPropertyNames()` 都只检查对象自身，不会向上遍历原型链。

**Object 自有属性方法的区别**

| 方法                                  | 自身可枚举字符串属性 | 自身不可枚举字符串属性 | 自身 Symbol 属性 | 原型链属性 |
| ----------------------------------- | ---------: | ----------: | -----------: | ----: |
| `Object.keys(obj)`                  |          ✅ |           ❌ |            ❌ |     ❌ |
| `Object.getOwnPropertyNames(obj)`   |          ✅ |           ✅ |            ❌ |     ❌ |
| `Object.getOwnPropertySymbols(obj)` |          ❌ |           ❌ |            ✅ |     ❌ |
| `Reflect.ownKeys(obj)`              |          ✅ |           ✅ |            ✅ |     ❌ |

可以把“自有属性”理解为直接写在当前对象这一层的属性；通过原型继承来的属性属于更上一层。

```js
const parent = { inherited: '来自原型' }
const symbolKey = Symbol('id')
const obj = Object.create(parent)

obj.visible = '可枚举属性'
Object.defineProperty(obj, 'hidden', {
  value: '不可枚举属性',
  enumerable: false,
})
obj[symbolKey] = 'Symbol 属性'

Object.keys(obj)                  // ['visible']
Object.getOwnPropertyNames(obj)   // ['visible', 'hidden']
Object.getOwnPropertySymbols(obj) // [symbolKey]
Reflect.ownKeys(obj)              // ['visible', 'hidden', symbolKey]s

Object.getPrototypeOf(obj)        // parent
'inherited' in obj                // true，会沿原型链查找
Object.hasOwn(obj, 'inherited')   // false，只判断对象自身
```

**为什么要使用这些方法**

- **渲染普通对象的字段：** 用 `Object.keys()`，通常只关心业务代码主动暴露的可枚举字段。
- **调试或检查完整的字符串属性：** 用 `Object.getOwnPropertyNames()`，它还能看到不可枚举属性。
- **框架或底层工具使用 Symbol 作为内部标识：** 用 `Object.getOwnPropertySymbols()`。
- **需要一次拿全所有自有键：** 用 `Reflect.ownKeys()`。
- **区分“对象自己的属性”和“继承的属性”：** 分别使用 `Object.hasOwn(obj, key)` 与 `key in obj`。

> [!NOTE]
> 属性是否“可枚举”和属性是否“属于自身”是两件事。`Object.keys()` 同时要求“自身 + 可枚举 + 字符串键”；`Object.getOwnPropertyNames()` 只放宽了“可枚举”限制，仍然不会读取原型链。

参考：[MDN：对象的可枚举性和所有权](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide/Enumerability_and_ownership_of_properties)、[MDN：Reflect.ownKeys](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Reflect/ownKeys)



### Set + computed：人员互斥选择

```
const participantIdSet = computed(
  () => new Set(formData.participantIds.map(String))
)
```

`map(String)` 统一 ID 类型，`.has(id)` 判断人员是否已选。

####  查找复杂度

- 数组 `.includes()`：最坏 **O(n)**，需要逐个查找。
- Set `.has()`：常见实现平均 **O(1)**，适合反复查询。
- 创建 Set 通常需要 **O(n)**。[参考](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Set)

####  computed：缓存 + 响应式

- **数组没变**：复用缓存，不重复创建 Set。
- **数组变化**：缓存失效，下次读取时重建 Set。
- 模板自动更新，不需要额外写 `watch`。[参考](https://vuejs.org/guide/essentials/computed.html)

```
:disabled="participantIdSet.has(String(user.id))"
```

#### 取消勾选的数据流

```
用户取消勾选
→ v-model 更新 formData
→ computed 缓存失效，模板读取时重建 Set
→ has(id) 返回 false
→ disabled 变为 false
→ 对方下拉自动解禁
```

**数组存选择，Set 快速查找，computed 自动同步。**
