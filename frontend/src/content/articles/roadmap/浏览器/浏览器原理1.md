1.Nginx 的兜底作用：就是保证【刷新、直接访问子路由地址】的时候，浏览器能拿到 index.html，给前端 JS 一个启动的机会。

❓为什么刷新后 JS 运行环境销毁了？
⚪ 刷新后
- 旧页面的把当前页面实例、DOM、CSSOM、JS 运行时全部销毁，
- 浏览器导航到当前 URL（history / hash + Nginx
- 然后重新加载资源、重新解析、重新执行。 
⚪所以有些数据你想他存在，必须要存在 localStorage、sessionStorage, URL这个浏览器本地”永久“存储的内存RAM 中。

❓刷新行为有很多种，在发送给 nginx 之前，有可能会被四层缓存拦住，因为缓存本身有可能会将 js html css 文件存下来，也就是说文件没过期

| 刷新方式        | 快捷键                       | bfcache | HTTP 缓存 | SW Cache | 网络请求 |
| ----------- | ------------------------- | ------- | ------- | -------- | ---- |
| **普通刷新**    | F5 / Ctrl+R               | ❌ 失效    | ✅ 用     | ✅ 用      | 可能不发 |
| **强制刷新**    | Ctrl+Shift+R / Ctrl+F5    | ❌ 失效    | ❌ 绕过    | ✅ 用      | 一定发  |
| **清空缓存刷新**  | DevTools 里勾 Disable cache | ❌       | ❌       | ❌        | 一定发  |
| **地址栏回车**   | 输入 URL + Enter            | ❌       | ✅       | ✅        | 可能不发 |
| **前进/后退**   | ← → 按钮                    | ✅ 恢复    | 不走      | 不走       | 不发   |
| **关闭标签再打开** | —                         | ❌       | ✅       | ✅        | 可能不发 |
