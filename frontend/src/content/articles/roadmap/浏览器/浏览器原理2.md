**JS V8 运行时：**代码先以“**磁盘上的字节**”存在，**运行时**把这些内容放入**内存**，经过解析得到结构，再由解释器执行（这一步已经是机器码了），解释器发现热点，继续由编译器翻译成机器码，最后由 **CPU 执行**。
```mermaid
flowchart LR
    SRC[源码 JS] -.保存为.-> DISK[磁盘/硬盘上的字节<br/>文本文件也是字节]

    DISK -->|操作系统/运行时读取| RAM[内存 RAM]
    RAM --> SRCMEM[内存中的源码字符串]

    SRCMEM --> PARSER[V8解析器 Parser]
    PARSER --> AST[AST 抽象语法树]
    AST --> BYTECODE[Ignition生成字节码]

    BYTECODE --> INT[Ignition解释器<br/>逐步执行字节码]
    INT --> HOT{达到热点阈值？}

    HOT -- 否：冷代码 --> INT
    HOT -- 是：热代码 --> JIT[V8 JIT编译器]
    JIT --> MC[生成机器码]
    MC -->|存入| CODE[内存中的代码区<br/>可执行代码空间]

    INT -.解释器本身也是机器码.-> CPU[CPU执行机器码]
    CODE --> CPU

    RAM --> HEAP[堆<br/>对象、数组、字符串]
    RAM --> STACK[栈<br/>调用帧、部分局部变量]

    RT[运行时 Runtime<br/>类型反馈、GC、加载器] -.负责调度和反馈.-> INT
    RT -.管理.-> RAM
    RT -.触发.-> JIT

    RT <--> OS[操作系统]
    OS <--> DISK
```

### JS、V8、解释器、编译器之间的关系
JIT，Just-In-Time Compilation: 边运行边编译 ：先解释执行，运行过程中发现热点代码，再即时编译
热代码：字节码 → JIT编译器 → 机器码 → 存入内存 → CPU执行机器码
冷代码：字节码 → Ignition解释器 → CPU执行解释器机器码
```mermaid
flowchart LR
    A[".js 源代码"] --> B["V8 解析器"]
    B --> C["AST 语法树"]
    C --> D["V8 解释器生成的字节码"]
    D --> E["先执行 发现经常运行的热点代码"]
    E --> F["运行时收集热点信息"]
    F --> G["JIT 优化编译器：V8 编译器把 经常被执行的 '热点代码' 编译成更快的机器码"]
    G --> H["CPU"]
```
#### 解析器和解释器不是一回事

| 组件              | 主要工作                     |
| --------------- | ------------------------ |
| 解析器 Parser      | 看代码是否符合语法，并构造 AST        |
| 解释器 Interpreter | 执行字节码或其他中间表示             |
| 编译器 Compiler    | 把代码翻译成更低层的表示，最终可以生成机器码   |
| 运行时 Runtime     | 提供内存管理、对象系统、异常、函数调用等执行环境 |

E.g: 
```js
let x = 1 + 2;
```

```mermaid
flowchart LR
    A[源码] --> B[解析器识别变量声明、加法表达式]
    B --> C[生成AST抽象语法树]
    C --> D[V8生成字节码]
    D --> E[解释器执行字节码]
    E --> F{代码反复执行？}
    F --是--> G[JIT编译成机器码]
    F --否--> END[结束]
    G --> END
```

### 磁盘和内存
1. 磁盘/SSD固态硬盘（静态）
	保存的是可执行文件：二进制指令、常量、代码段。
	.xxx 程序/Java文件/源代码
2. 内存（运行时）
	保存**程序指令 + 当前执行位置 + 变量 / 上下文等全部运行时状态**。
	程序加载进内存后，操作系统会创建进程
