# 堆、线程栈与垃圾回收

## 线程栈：函数调用的临时空间

线程创建时会准备线程栈。函数调用时，栈上增加栈帧；函数返回时，栈帧通常被移除。

```js
function add(a, b) {
  const result = a + b;
  return result;
}
```

递归过深或同步调用层次过深，可能出现：

```text
Maximum call stack size exceeded
```

## 堆：动态对象的存放区域

对象、数组和许多字符串等动态数据通常位于 JavaScript 引擎管理的堆中。堆由运行时和垃圾回收器管理，不需要前端手动 `free`。

常见内存泄漏来源：

```js
const cache = [];

function save(data) {
  cache.push(data); // 一直增长且不清理
}
```

还要留意没有移除的事件监听器、没有清理的定时器、长期存在的闭包和无限增长的全局缓存。

## 实际排查方法

在 Chrome DevTools 中可以使用 Memory 面板创建 Heap Snapshot，比较多次快照中仍然增长的对象；使用 Performance 面板观察内存曲线和长任务。

## 一个边界

局部变量不一定永远在栈上。优化后它可能在寄存器中，或者被编译器消除。前端使用“栈”和“堆”时，应把它们当作有用的模型，而不是绝对的物理位置。
