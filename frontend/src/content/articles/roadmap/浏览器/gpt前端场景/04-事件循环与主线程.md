# 事件循环、调用栈与主线程

浏览器主线程既要执行 JavaScript，也要参与样式计算、布局、绘制和用户输入处理。

简化模型：

```text
调用栈执行同步代码
  → 栈清空
  → 执行微任务（Promise 回调）
  → 浏览器安排渲染
  → 执行任务（例如定时器、用户事件）
```

真实调度还受规范、浏览器实现和任务来源影响，上图是帮助理解的简化模型。

## 为什么页面会卡

如果一个同步函数持续占用主线程，浏览器就没有机会及时处理点击、滚动和绘制：

```js
while (true) {
  // 主线程永远无法返回事件循环
}
```

实际项目中，长循环、大量 JSON 处理、复杂排序和频繁布局读取，都可能造成长任务。

## 前端处理方式

- 把大任务拆成小块，让主线程有机会处理输入和绘制。
- 用 `requestAnimationFrame` 配合分帧更新。
- 把不需要 DOM 的重计算放进 Web Worker。
- 使用 Performance 面板查找 Long Task。
