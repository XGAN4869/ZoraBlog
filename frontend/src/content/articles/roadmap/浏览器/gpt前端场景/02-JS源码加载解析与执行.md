# JS 源码加载、解析与执行

## V8 的简化链路

```text
网络、缓存或磁盘中的字节
  → 内存中的源码字符串
  → Parser 解析
  → AST 抽象语法树
  → Ignition 生成字节码
  → Ignition 解释器执行字节码
```

浏览器中的源码不一定直接来自磁盘，也可能来自网络或 HTTP 缓存。操作系统负责底层的文件和内存管理，浏览器运行时负责读取和交给 V8。

## 字节码不是机器码

- JavaScript 源码：人可以阅读的文本。
- AST：按语法组织起来的树形结构。
- 字节码：V8 使用的中间指令，CPU 不能直接执行。
- 机器码：适合当前 CPU 的指令，CPU 可以执行。

因此，CPU 不会直接执行 JavaScript 字节码。冷代码由 Ignition 解释器处理，而 Ignition 自己是用机器码运行的程序。

## 对前端有什么用

JavaScript 包太大，可能增加下载、解析、编译和首次执行时间。因此代码分割、路由懒加载和减少首屏脚本，能够改善启动速度。
