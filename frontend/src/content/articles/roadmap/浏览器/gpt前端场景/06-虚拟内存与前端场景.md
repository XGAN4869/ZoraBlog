# 虚拟内存与前端场景

## 虚拟内存地图是什么

每个进程都有自己的虚拟地址空间。操作系统在地图中安排代码、动态库、堆、内存映射区和线程栈，并设置读、写、执行权限。

```text
虚拟地址
  → 页表和 CPU 的内存管理单元
  → 物理 RAM 中的页面
```

虚拟地址不等于物理 RAM。有些页面可以按需加载，或者暂时由文件和交换空间支撑。

## 为什么需要它

- 隔离不同进程的内存，提高安全性。
- 让程序使用连续、方便的地址空间。
- 支持动态库、共享内存和按需加载。
- 通过权限限制，避免数据区被当作代码执行。

## 前端相关场景

- 浏览器标签页通常运行在受隔离的渲染进程中。
- 一次性创建巨大数组、加载大量图片或保存过多缓存，可能导致标签页崩溃。
- Node.js 处理大文件或大 JSON 时，可能出现 `JavaScript heap out of memory`。
- 代码分割和懒加载能减少启动时需要加载、解析和占用的内容。

## 不需要做什么

普通前端代码不需要手动建立虚拟内存地图。理解它主要是为了知道进程隔离、内存上限和崩溃原因。
