# 浏览器原理与前端场景：学习路线

这组文档回答一个实际问题：浏览器底层的进程、线程、内存、解析、解释执行和 JIT，分别会在前端工作中什么时候帮上忙。

## 先记住一条主线

```text
浏览器进程启动
  → 加载网页资源
  → JavaScript 被读取和解析
  → 生成字节码
  → 解释器执行
  → 热点代码可能被 JIT 编译
  → CPU 执行机器码
```

这不是每种语言、每个浏览器都完全相同的实现细节，而是理解 JavaScript/V8 的简化模型。

## 这些知识分别解决什么问题

| 概念 | 前端常见问题 |
| --- | --- |
| 进程、线程 | 页面卡顿、Web Worker、浏览器多进程 |
| 调用栈 | 递归报错、同步代码阻塞、异步执行顺序 |
| 堆 | 内存泄漏、页面越来越卡、标签页崩溃 |
| 事件循环 | Promise、定时器、UI 更新顺序 |
| 解析、字节码、JIT | 首屏速度、重复计算性能 |
| 虚拟内存 | 进程隔离、内存溢出、按需加载 |

## 一个重要边界

“JavaScript 运行时”是执行 JavaScript 的软件环境，例如 V8、SpiderMonkey、JavaScriptCore、Node.js 的运行环境。它不是操作系统的“运行态”。

“运行态”通常描述某个线程此刻是否正在被操作系统调度使用 CPU。一个 JavaScript 运行时可以存在，但它的线程此刻可能正在运行、就绪，或等待 I/O。
