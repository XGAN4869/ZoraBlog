# 热代码、冷代码与 JIT

## 怎么判断

V8 会根据运行时信息判断某个函数或循环是否“热”，例如调用次数、循环次数、类型反馈和分支行为。热点阈值不是一个固定、适用于所有版本的公开数字。

```text
很少执行 → 冷代码
反复执行 → 热代码
```

## 两条执行路径

```text
冷代码：字节码 → Ignition解释器 → CPU执行解释器机器码
热代码：字节码 → JIT编译器 → 机器码 → CPU执行机器码
```

不是每条 JavaScript 指令同时被解释和编译。通常是解释器先让代码快速运行，热点代码达到条件后再编译；编译可能在后台进行。

## JIT 能带来什么

JIT 可以针对实际运行情况进行类型特化、函数内联、循环优化和减少重复检查，从而提高反复执行路径的速度。

JIT 也有成本：编译需要时间和内存。如果之前的类型假设失效，运行时可能反优化，退回解释执行。

## 前端应该怎么用这条知识

不要先追求“迎合 JIT”。优先优化算法复杂度、减少重复计算、减少不必要的对象创建和 DOM 操作。性能问题应通过 Performance 等工具测量后再决定。
