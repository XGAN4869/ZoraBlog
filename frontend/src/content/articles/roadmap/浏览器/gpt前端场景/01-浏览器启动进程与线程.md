# 浏览器启动、进程与线程

## 点击浏览器图标后发生什么

简化流程如下：

```text
点击 Chrome
  → 操作系统加载 Chrome 可执行文件
  → 创建进程并分配 PID
  → 建立进程的虚拟地址空间
  → 创建线程
  → 线程进入就绪队列
  → 调度器让线程运行
  → CPU 执行 Chrome 的机器码
```

这里的 PID、就绪队列和调度器都属于操作系统层面。

## Chrome 不只有一个进程

现代浏览器通常会拆成多个进程，例如浏览器进程、渲染进程、GPU 进程和网络进程。具体拆分会因浏览器版本和系统而变化。

网页中的 JavaScript 通常在某个渲染进程的线程中运行，而不是简单地在一个“Chrome 总线程”里运行。一个页面还可能创建 Web Worker，每个 Worker 使用独立线程。

## 对前端有什么用

- 页面主线程执行太久，会阻塞点击、滚动和绘制。
- 重计算可以考虑放入 Web Worker，但 Worker 不能直接操作 DOM。
- iframe 和不同站点的进程隔离，是浏览器安全模型的一部分。
- 页面崩溃不一定等于整个浏览器崩溃，常见情况是某个渲染进程崩溃。

## 不要混淆

进程是资源和内存隔离的单位；线程是执行指令的单位。CPU 实际调度的是线程。
