### 不装 TypeScript 为什么 `.ts` 还能运行？
因为 Vite/VitePress 会通过 esbuild 把 `.ts` 文件转换成 JavaScript，所以：
- **运行、打包 `.ts` 文件**：通常不必安装 `typescript`
- **执行完整类型检查、运行 `tsc`**：需要安装 `typescript`
- **检查 `.vue` 文件中的 TypeScript**：建议同时安装 `vue-tsc`

### 各个配置文件职责

| 配置                                                    | 用途                                                                    |
| ----------------------------------------------------- | --------------------------------------------------------------------- |
| `config.mts`<br>                                      | 管 **Vite 运行时代码解析（实际打包、浏览器运行）**                                        |
| `tsconfig.json` <br>一个管 **TS 类型识别（编辑器、vue‑tsc 类型检查）** | 是“告诉 TypeScript 应该怎样检查和编译这个项目”的配置文件。<br>可以把它看成 TypeScript 项目的“规则说明书”。 |
| `typescript` + `vue-tsc`                              | 真正执行 TypeScript 和 Vue 类型检查                                            |

### vue-tsc 使用
**`vue‑tsc`** TS 原生 `tsc` 不认识 `.vue` SFC 单文件组件。 `vue‑tsc` 是 Vue 官方封装的类型检查工具，可以解析 `.vue` 文件里的 `<script setup>`，做完整类型校验。 no‑emit = **不输出任何编译产物，只做类型检查** 只跑类型扫描、报错；**不会生成 js、d.ts 文件，不写磁盘**
```json
"type-check": "vue-tsc --noEmit"
```

### package.json 文件编写
#### scripts 脚本段（npm run xxx 执行）
> `prepare` 是 npm 的**生命周期钩子**。
- 执行时机：`npm install` 安装完依赖之后自动运行。
- 作用：初始化 husky，安装 git hooks（git 钩子）。 husky 可以劫持 git 命令，比如执行 `git commit` 提交代码前跑自定义脚本。
效果：别人 clone 项目执行 npm install，会自动装好 git 钩子，不用手动配置 husky。

> lint:
- lint:lint-eslint ：扫描**项目全部文件**，做 ESLint 
- lint::lint-prettier：检查项目全部文件格式是否符合 prettier 格式化规则 
- lint::lint-staged" ：只处理 git 已经 add 放入暂存区的文件
#### 完整工作流（husky + lint‑staged）

1. 你执行 `git add .` → 文件进入 git 暂存区
2. 执行 `git commit -m "xxx"`
3. husky 触发 `pre‑commit` 钩子，运行 `npm run lint:lint‑staged`
4. lint‑staged 拿到暂存文件：执行 eslint 修复 + prettier 格式化
5. 如果 eslint 有无法自动修复的错误 → 直接终止 commit，不让提交代码；你必须改完错误才能提交。
