# TS13：类型推论与类型别名

## 一、类型推论（Type Inference）

TypeScript 会根据变量的初始值、函数返回值和上下文，自动推断出更合适的类型。能推断清楚时，不必重复书写类型注解。

```ts
let count = 1               // number
const title = 'TypeScript'  // 'TypeScript'（const 的字面量类型）
let names = ['Zora', 'Raechel'] // string[]
```

### 1. `let` 与 `const` 的推论差异

```ts
let status = 'loading'      // string：后续允许改成其他字符串
const fixedStatus = 'done'  // 'done'：值不可重新赋值
```

如果变量之后要接收更宽的范围，可以显式写出类型：

```ts
let status: 'loading' | 'success' = 'loading'
status = 'success'
```

### 2. 没有初始值时

没有初始值、又没有类型注解时，TypeScript 会根据编译配置推断类型；在严格模式下通常会把它推断为 `any` 或报“隐式 any”警告。因此，函数参数、类属性等位置不要依赖隐式 `any`：

```ts
let result: unknown // 暂时不知道类型时，unknown 比 any 更安全
```

> `any` 会关闭大部分类型检查；`unknown` 必须经过判断或断言后才能使用。

## 二、类型别名 `type`

类型别名给一个类型起名字，可以复用基础类型、联合类型、元组、对象结构等：

```ts
type StringOrNumber = string | number

let value: StringOrNumber = 'Zora'
value = 18
```

类型别名只存在于编译期，不能在运行时通过 `console.log` 或 `typeof` 读取。

### 1. 类型别名描述对象

```ts
type User = {
  id: number
  name: string
  age?: number
}
```

### 2. 类型别名描述联合、元组和函数

```ts
type Status = 'idle' | 'loading' | 'success' | 'error'
type Point = [number, number]
type Formatter = (value: number) => string
```

## 三、`type` 与 `interface` 的区别

| 对比项 | `type` | `interface` |
|---|---|---|
| 联合类型 | 直接写 `type ID = string \| number` | 不能直接用 `interface` 表示联合类型 |
| 对象继承/组合 | 使用交叉类型 `A & B` 或条件类型 | 使用 `extends` |
| 同名声明 | 不能重复声明同名别名 | 同名接口可以自动合并 |
| 适合场景 | 联合、元组、函数、映射和条件类型 | 对象结构、类契约、可扩展公共 API |

```ts
interface UserBase {
  id: number
}

interface Admin extends UserBase {
  permissions: string[]
}

type UserWithToken = UserBase & {
  token: string
}
```

`type` 不是“低级版 interface”，两者都能描述对象结构，应根据场景选择。

## 四、条件类型中的 `extends`

在条件类型中，`extends` 表示“左侧类型是否可以赋值给右侧类型”，不是类继承：

```ts
type IsNumber = number extends string ? true : false // false
type IsLiteral = 1 extends number ? true : false     // true
type NeverCheck = 1 extends never ? 1 : 0            // 0
```

可以把它读成：如果左边是右边的子类型（可赋值给右边），就选择 `?` 后面的类型，否则选择 `:` 后面的类型。

常见的宽窄关系可以粗略理解为：

```text
never  ⊆  字面量类型  ⊆  string / number  ⊆  unknown
any   可以绕过大部分检查（不要把它当作正常的子类型关系）
```

## 五、类型推论与显式注解的建议

1. 初始值已经能清楚表达类型时，让 TypeScript 推论即可。
2. 函数参数、公共 API、空数组或后续会改变范围的变量，建议显式写类型。
3. 外部数据不可信时使用 `unknown`，先做运行时校验再收窄。
4. 需要表达联合、元组或条件类型时使用 `type`；需要可扩展对象契约时优先考虑 `interface`。
