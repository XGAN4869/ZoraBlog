# TS11：元组类型（Tuple）

## 一、元组是什么

元组是**长度固定、每个位置类型可以不同的数组**。它适合表达“位置有明确含义”的数据，例如坐标、键值对或固定表头的一行数据。

```ts
// 第 1 项必须是 number，第 2 项是可选的 number
const point: [x: number, y?: number] = [1]
const point2: [x: number, y?: number] = [1, 2]
```

### 数组和元组的区别

| 类型 | 特点 | 示例 |
|---|---|---|
| `number[]` | 长度不固定，所有元素都是 `number` | `[1, 2, 3]` |
| `[string, number]` | 长度和位置固定，第一项是字符串、第二项是数字 | `['Zora', 23]` |

## 二、常见使用场景：固定表头的数据

例如 Excel 中每一行都按“姓名 + 年龄”的顺序保存：

```ts
// 外层数组可以有多行；每一行必须是 [string, number]
const excel: [name: string, age: number][] = [
  ['Zora', 23],
  ['Raechel', 22],
]

const firstRow = excel[0]
console.log(firstRow[0]) // Zora
console.log(firstRow[1]) // 23
```

如果把年龄写成字符串，或者调换两个位置，TypeScript 会在编译期提示错误。

## 三、只读元组

`readonly` 可以阻止通过这个变量修改元组内容：

```ts
const rgb: readonly [number, number, number] = [255, 0, 0]
// rgb[0] = 0       // Error：只读元组不能修改
// rgb.push(1)      // Error：只读元组没有可变的 push 操作
```

> `readonly` 只限制当前元组引用的修改，不代表元组中嵌套对象会自动深度冻结。

## 四、可选项与剩余项

### 1. 可选元素

可选元素使用 `?`，并且必须放在必选元素之后：

```ts
type Response = [status: number, message?: string]

const ok: Response = [200]
const error: Response = [500, '服务器错误']
```

### 2. 剩余元素

剩余元素可以表示“前面的位置固定，后面可以有任意多个同类型值”：

```ts
type Scores = [name: string, ...scores: number[]]

const student: Scores = ['Zora', 90, 95, 88]
```

## 五、读取元组的类型信息

`type` 和 `interface` 是编译期类型，不是运行时变量，不能通过 `console.log` 直接打印类型。可以使用 `typeof` 在类型位置提取信息：

```ts
const arr: readonly [x: number, y?: number] = [1]

type FirstType = typeof arr[0]       // number
type ArrLength = typeof arr['length'] // 1 | 2
```

这里的 `typeof` 与 JavaScript 运行时的 `typeof` 不同：它出现在类型位置，用于生成新的类型。

## 六、复习要点

1. 元组是“有顺序、有位置含义”的数组。
2. 元组可以限制长度、每一项的类型和可选项。
3. `readonly` 元组适合表示不应该被修改的固定数据。
4. 需要任意长度、同一类型的集合时，使用普通数组类型更合适。
