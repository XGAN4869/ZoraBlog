## 登录认证方式
```
认证（Authentication）
  ├─ Basic Auth           ← 最原始，明文 base64，配 HTTPS 才勉强能用
  ├─ Session + Cookie     ← 传统 Web，服务端存 session
  ├─ JWT (Token)          ← 现代前后端分离主流
  ├─ OAuth2 / OIDC        ← 第三方登录（微信、GitHub）
  ├─ API Key              ← 服务间调用
  ├─ SSO 单点登录          ← 企业内多系统
  └─ ...
```

## jwt
[text](https://www.tizi365.com/course/go-jwt)
- 如果不加 json:"user_id" 标签，Go 序列化出来的 JSON 键名就是 UserID（大写）。为了让前端/其他服务能统一用 user_id，我们加这个标签。
- 不仅前端/后端需要，在 JWT 的场景下，是因为 JWT 规定其 Payload 必须是一个 JSON 对象，然后再进行 Base64Url 编码。
- RegisteredClaims 也会被 JSON 化，只是库已经替你写好了标签
```
Header → JSON → Base64URL 编码 ─┐
                               ├→ header.payload
Claims → JSON → Base64URL 编码 ─┘
                                      ↓
                             用 secretKey 计算签名
                                      ↓
                            header.payload.signature
```
