## 2. 加「文章」模块

按第 5 节的分层规则，**只新增文件，不改旧文件**。

### ① `internal/model/post.go`

```go
package model

import "time"

// Post 对应数据库里的 posts 表。
type Post struct {
	ID       uint   `gorm:"primaryKey" json:"id"`
	Title    string `gorm:"size:200;not null" json:"title"`
	// Slug 是 URL 里用的短标识，比如 /posts/hello-world。
	// uniqueIndex 保证不重复，否则两条文章会抢同一个网址。
	Slug     string `gorm:"size:200;uniqueIndex;not null" json:"slug"`
	Summary  string `gorm:"size:500" json:"summary"`
	// longtext 能存 4GB 文本，放 Markdown 正文
	Content  string `gorm:"type:longtext" json:"content"`
	// draft（草稿）/ published（已发布）
	Status   string `gorm:"size:16;index;not null;default:draft" json:"status"`
	// 指针类型：草稿时是 NULL。如果用 time.Time，零值会被存成 0001-01-01 这种垃圾数据
	PublishedAt *time.Time `json:"publishedAt"`

	// AuthorID 必须加 index，否则「查某人的所有文章」会全表扫描
	AuthorID uint `gorm:"index;not null" json:"authorId"`
	Author   User `gorm:"foreignKey:AuthorID" json:"author"`

	CreatedAt time.Time `json:"createdAt"`
	UpdatedAt time.Time `json:"updatedAt"`
}
```

> `PublishedAt` 用 `*time.Time` 而不是 `time.Time` 是个容易踩的坑：
> 后者是值类型，没赋值时会变成 Go 的零值 `0001-01-01`，写进数据库是个看起来像 bug 的日期。
> 指针类型可以明确表示「这里就是空的」。

### ② `internal/store/post.go`（含分页）

```go
package store

import (
	"errors"

	"fronted/internal/model"

	"gorm.io/gorm"
)

type PostStore struct {
	db *gorm.DB
}

func NewPostStore(db *gorm.DB) *PostStore {
	return &PostStore{db: db}
}

func (s *PostStore) Create(post *model.Post) error {
	err := s.db.Create(post).Error
	if errors.Is(err, gorm.ErrDuplicatedKey) {
		return ErrDuplicate // Slug 撞了
	}
	return err
}

func (s *PostStore) FindBySlug(slug string) (*model.Post, error) {
	var post model.Post
	// Preload("Author") 会自动把作者信息一起查出来，
	// 否则 post.Author 是个空对象，前端拿不到作者名。
	err := s.db.Preload("Author").Where("slug = ?", slug).First(&post).Error
	if err != nil {
		return nil, translate(err)
	}
	return &post, nil
}

// ListPublished 分页查已发布的文章，按发布时间倒序。
// 返回列表和总数——前端要总数才能算总页数。
func (s *PostStore) ListPublished(page, pageSize int) ([]model.Post, int64, error) {
	var total int64
	if err := s.db.Model(&model.Post{}).Where("status = ?", "published").Count(&total).Error; err != nil {
		return nil, 0, err
	}

	var posts []model.Post
	err := s.db.
		Preload("Author").
		Where("status = ?", "published").
		Order("published_at DESC").
		Limit(pageSize).
		// 第 1 页跳过 0 条，第 2 页跳过 pageSize 条
		Offset((page - 1) * pageSize).
		Find(&posts).Error

	return posts, total, err
}

func (s *PostStore) FindByID(id uint) (*model.Post, error) {
	var post model.Post
	if err := s.db.Preload("Author").First(&post, id).Error; err != nil {
		return nil, translate(err)
	}
	return &post, nil
}

func (s *PostStore) Update(post *model.Post) error {
	return s.db.Save(post).Error
}

// DeleteOwned 只删除属于 authorID 的文章。
// 把归属判断写进 WHERE 条件，而不是先查再判断——后者在并发下有被绕过的风险。
func (s *PostStore) DeleteOwned(id, authorID uint) error {
	result := s.db.Where("id = ? AND author_id = ?", id, authorID).Delete(&model.Post{})
	if result.Error != nil {
		return result.Error
	}
	if result.RowsAffected == 0 {
		// 要么文章不存在，要么不是你的。对外统一报「不存在」，不泄露别人的文章是否存在。
		return ErrNotFound
	}
	return nil
}
```

### ③ 一个必须守住的安全规则

**「只能改自己的文章」这个判断必须放在 service 层，不能只靠前端藏按钮。**

前端藏按钮只是体验优化，任何人打开 F12 就能自己发请求。所以 `Update` 和 `Delete`
必须带上归属校验。上面 `DeleteOwned` 就是把 `author_id = ?` 写进 SQL 的 WHERE 里，
属于安全的位置。

### ④ 分页的返回格式

```go
// internal/service/post.go 里

// Page 是分页结果的通用格式，前端按这个渲染分页器。
type Page[T any] struct {
	Items    []T   `json:"items"`
	Total    int64 `json:"total"`
	Page     int   `json:"page"`
	PageSize int   `json:"pageSize"`
}
```

返回给前端：

```json
{
  "data": {
    "items": [ { "id": 1, "title": "…" } ],
    "total": 42,
    "page": 1,
    "pageSize": 10
  }
}
```

前端拿到 `total` 和 `pageSize` 就能算总页数：`Math.ceil(total / pageSize)`。

### ⑤ 收尾要改的三处

| 文件 | 改什么 |
|------|--------|
| `internal/database/mysql.go` | `AutoMigrate(&model.User{}, &model.Post{})` |
| `internal/router/router.go` | 加一组 `/api/posts` 路由；写入接口挂在鉴权分组下 |
| `main.go` | 装配 `postStore → postService → postHandler`，塞进 `Dependencies` |

公开的读接口（列表、详情）**不挂鉴权**，写入接口（新建、改、删）**必须挂**：

```go
posts := api.Group("/posts")
{
	posts.GET("", deps.PostHandler.List)       // 不用登录，谁都能看
	posts.GET("/:slug", deps.PostHandler.Detail)

	auth := posts.Group("", middleware.RequireAuth(deps.JWTSecret))
	{
		auth.POST("", deps.PostHandler.Create)      // 必须登录
		auth.PUT("/:id", deps.PostHandler.Update)
		auth.DELETE("/:id", deps.PostHandler.Delete)
	}
}
```

## 3. 开发体验：加个热重载

现在是改一行代码就要 `Ctrl+C` 再 `go run .`。装个 Air 能自动重启，和 Vite 的 HMR 一个意思。

```powershell
go install github.com/air-verse/air@latest
```

> ⚠️ 老教程写的是 `github.com/cosmtrek/air`。**那个仓库已经迁移了**，
> 现在要用 `air-verse` 这个新地址，用旧的会报模块路径冲突。

Windows 上 `go install` 装的程序在 `GOPATH\bin` 里，可能不在 PATH 中。加一下：

```powershell
$env:Path += ";$(go env GOPATH)\bin"   # 只对当前窗口生效
```

想永久生效就把 `%USERPROFILE%\go\bin` 加进系统环境变量。

在 `backend/` 目录下初始化并使用：

```powershell
cd backend
air init     # 生成 .air.toml 配置文件
air
```

之后改任何 `.go` 文件都会自动重新编译重启。**编译失败时 Air 不会退出**，
仍然在监听——改好保存就行，这点比手动重启舒服。

> Air 会在 `backend/tmp/` 生成临时文件。你的 `backend/.dockerignore` 里已经排除了 `tmp`，
> 不会被误打进镜像，不用额外处理。建议再把这个目录写进 `.gitignore`。

## 4. 后面还想要的功能（按建议顺序）

| 顺序 | 功能 | 要点 |
|------|------|------|
| 1 | 改昵称 / 改密码 | 改密码要校验旧密码；改完旧 token 仍有效，这是已知短板 |
| 2 | 文章增删改查 + 分页 | 见上面第 2 节 |
| 3 | Markdown 渲染 | 前端用 `react-markdown`（默认安全）；别用 `dangerouslySetInnerHTML` |
| 4 | 分类 / 标签 | 多对多关系，需要中间表，GORM 用 `many2many` 标签 |
| 5 | 评论 | 需要新模块，注意做频率限制，否则会被灌垃圾 |
| 6 | 图片上传 | 存本地目录或对象存储；**必须校验文件类型和大小**，别信前端传来的文件名 |
| 7 | 草稿 / 定时发布 | `Post.Status` 字段已经预留了 |

**建议一个一个来**，每加一个就跑一遍完整流程（注册 → 登录 → 发文章 → 改 → 删）。
分层结构的意义就是让每次只动一小块，出问题好定位。

## 5. 上线前必须做的事

这些现在不做没问题，但**上线前一个都不能少**。

### 安全

- [ ] **换掉 `JWT_SECRET`**，用一个长随机字符串。可以用
  `openssl rand -base64 48` 或 PowerShell 的
  `[Convert]::ToBase64String((1..48 | % { Get-Random -Max 256 }))` 生成
- [ ] **确认 `.env` 没提交进 git**（你的 `backend/.dockerignore` 里已经排除了，`.gitignore` 也要确认）
- [ ] **删掉 compose 里的 `ports: 3306:3306`**，数据库不该对外暴露
- [ ] **不用 root 连数据库**，业务代码用 `ganblog` 这个账号（已经这么做了）
- [ ] MySQL 密码换成强密码，别用 `ganblogpass`
- [ ] 全站上 HTTPS，否则 token 在网络上明文传输

### 稳定性

- [ ] 加 `gin.Recovery()`（`gin.Default()` 已自带）并**把日志写到文件**，别只打控制台
- [ ] 数据库加定时备份
- [ ] 加个 `/api/health` 之外的存活检查，确认真实可用（现在这个只检查进程活着，不检查数据库通不通）

### 运维

- [ ] 确认 `docker compose down` 不会丢数据（数据在 `mysql-data` 卷里，安全）
- [ ] 给自己留一份恢复流程的记录：怎么从零把服务拉起来

## 6. 最后一点建议

**别一次做完。** 这个项目最大的风险不是技术难，是功能铺太开、每块都半成品，
最后改不动也懒得看。

推荐的节奏：**一次只加一个模块，加完立刻在浏览器里点一遍完整流程，确认没坏再去下一个。**

分层的价值就在这里——只要你守住「依赖只能单向向下」那一条，
加十个模块也不会把已有的搞坏。第 5 节那三条箭头规则，是整个项目最值得记住的东西。
