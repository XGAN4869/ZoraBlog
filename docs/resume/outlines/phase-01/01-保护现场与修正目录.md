# 01 · 保护现场与修正目录

目标：**把 `fronted` 正确整理为 `frontend`，同时确保当前 Go 学习代码和笔记一行不丢。**

这一篇不写业务代码。先让仓库状态变得可信，后面的重构才有安全基础。

## 1. 先读懂当前状态

在仓库根目录执行：

```powershell
git status --short
```

当前会看到三类信息：

```text
M  backend/main.go
M  backend/notes/knowledge.md
D  fronted/...
?? frontend/
```

含义：

- `M`：文件在上次提交后被修改，里面是你正在学习时写的内容。
- `D`：Git 记录中的旧路径已经消失。
- `??`：新目录存在，但还没有加入 Git 索引。

Git 尚未把它显示成 `R`（rename），不代表文件丢失。Git 的重命名识别发生在比较内容时，本质仍然是“旧文件删除 + 内容相同的新文件加入”。

## 2. 禁止做的事

不要执行：

```powershell
git reset --hard
git checkout -- backend/main.go
git clean -fd
```

这些命令可能直接丢掉未提交的学习内容或整个 `frontend/`。

这一单元只允许：查看、比较、修改明确路径、运行构建与 lint。

## 3. 确认新目录内容完整

先检查关键文件：

```powershell
Test-Path frontend/package.json
Test-Path frontend/src/App.tsx
Test-Path frontend/Dockerfile
Test-Path frontend/nginx.conf
```

四条都应该返回 `True`。

再比较旧提交与新目录中的关键文件：

```powershell
git show HEAD:fronted/package.json
Get-Content -Raw frontend/package.json
```

允许修改项目名称和路径，但依赖、脚本和业务源码不能无故消失。

## 4. 需要修正的引用

先搜索旧拼写：

```powershell
rg -n "fronted" README.md compose.yaml frontend backend docs/resume
```

本单元需要处理：

| 文件 | 修改 |
|---|---|
| `compose.yaml` | `context: ./fronted` 改为 `context: ./frontend` |
| `README.md` | 所有前端命令路径改为 `frontend`，删除已经过期的“后端没有代码”描述 |
| `frontend/package.json` | `name` 从 `fronted` 改为 `frontend` |
| `frontend/package-lock.json` | 根级 `name` 与 package 记录同步改为 `frontend` |
| `frontend/README.md` | 如果存在旧路径，同步修正 |

暂时不要修改 `backend/main.go`。

## 5. 验证前端没有因改名损坏

```powershell
cd frontend
npm run lint
npm run build
```

预期：

- ESLint 退出码为 0。
- TypeScript 和 Vite 构建成功。
- `dist/` 中生成 `index.html` 与 assets。

回到根目录再次搜索：

```powershell
cd ..
rg -n "fronted" README.md compose.yaml frontend backend docs/resume
```

设计规格中描述“历史上叫 fronted”的句子可以保留；运行命令和配置不能再指向旧目录。

## 6. 让 Git 识别本次改名

确认文件完整、构建通过后才执行：

```powershell
git add -A -- fronted frontend README.md compose.yaml
git status --short
```

Git 可能显示 `R`，也可能仍显示一组删除和新增。两者都可以；重要的是新目录内容完整、旧路径不再被运行配置引用。

不要顺手暂存 `backend/main.go` 和 `backend/notes/knowledge.md`，它们是另一组学习改动。

## 7. 完成检查

- [x] `frontend/` 关键文件全部存在。
- [x] README 和 Compose 使用 `frontend`。
- [x] npm 包名已同步。
- [x] `npm run lint` 通过。
- [x] `npm run build` 通过。
- [x] `backend/main.go` 和知识笔记仍保留原修改。
- [x] 已阅读 `git status`，确认没有意外删除。
