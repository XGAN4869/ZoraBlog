# 08 · 前后端最小测试

目标：**让 Go 和 React 都有会真正执行的测试，而不只是“构建没报错”。**

## 1. 构建与测试的区别

```text
构建通过：语法和类型基本正确，能生成程序。
测试通过：指定输入得到了期望行为。
```

当前 `go test ./...` 显示 `[no test files]`，命令退出成功，但没有验证任何业务行为。

Phase 01 结束时至少要有：

- 配置加载测试。
- Router/健康检查测试。
- 数据库失败测试。
- React 最小渲染测试。

## 2. Go 测试组织

推荐就近放置：

```text
internal/config/config.go
internal/config/config_test.go

internal/health/handler.go
internal/health/handler_test.go

internal/server/router.go
internal/server/router_test.go
```

Go 的 `_test.go` 只在 `go test` 时编译，不会进入生产二进制。

运行全部测试：

```powershell
cd backend
go test ./...
```

需要查看具体测试名：

```powershell
go test ./... -v
```

竞态检查可在当前阶段加入：

```powershell
go test -race ./...
```

如果 Windows 环境的 race 构建受到 CGO 工具链限制，记录真实错误，不把它伪装成业务测试失败。

## 3. 前端安装 Vitest

在 `frontend/` 中：

```powershell
npm install -D vitest jsdom @testing-library/react @testing-library/jest-dom @testing-library/user-event
```

这些依赖分别负责：

- `vitest`：测试运行器。
- `jsdom`：在 Node 环境模拟浏览器 DOM。
- `@testing-library/react`：按用户看到的内容测试组件。
- `jest-dom`：提供更易读的 DOM 断言。
- `user-event`：模拟用户点击和输入。

## 4. 增加测试脚本

`frontend/package.json`：

```json
{
  "scripts": {
    "test": "vitest run",
    "test:watch": "vitest"
  }
}
```

保留已有的 `dev`、`build`、`lint` 和 `preview`。

## 5. 测试环境配置

可以在 `vite.config.ts` 中加入测试配置，或者单独建立 `vitest.config.ts`。首版保持最小，使用与 Vite 相同的 React 插件即可。

测试环境目标：

```text
environment: jsdom
setupFiles: ./src/test/setup.ts
```

`src/test/setup.ts`：

```ts
import '@testing-library/jest-dom/vitest'
```

## 6. 写最小烟雾测试

当前 App 仍是 Vite 起始页面，因此测试现有可见文本即可：

```text
frontend/src/App.test.tsx
```

```tsx
import { render, screen } from '@testing-library/react'
import { describe, expect, it } from 'vitest'
import App from './App'

describe('App', () => {
  it('renders the starter heading', () => {
    render(<App />)
    expect(screen.getByRole('heading', { name: 'Get started' })).toBeInTheDocument()
  })
})
```

先运行测试。若配置尚未完成，它应该因缺少 jsdom/setup 或断言扩展而失败；补齐最小配置后再运行到通过。

这个测试以后可以随着首页重做而替换，它现在的价值是证明测试链路正常。

## 7. 最终验证命令

```powershell
cd backend
go test ./...
go build ./...

cd ..\frontend
npm run test
npm run lint
npm run build
```

所有命令都必须实际执行并查看退出码。

## 8. 完成检查

- [ ] Go 至少执行配置与健康检查真实测试。
- [ ] `go test ./...` 不再出现所有包都 `[no test files]`。
- [ ] 前端 test 脚本存在。
- [ ] React 烟雾测试真实执行。
- [ ] npm test、lint、build 全部通过。
- [ ] 没有为了让测试通过而删除有效断言。
