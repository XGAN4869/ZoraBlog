# 03 · 用户模块（内存版）

**这一节就是你要的「最小例子」**：一个完整可用的用户模块，
包含注册、登录、JWT 鉴权、获取当前用户，全部塞在**一个 `main.go` 里**，能直接跑。

**数据存在内存里**，所以重启服务数据就没了——这是故意的。
先用最快的速度让前端能调通，第 4 节再换成 MySQL，那时候你已经有东西可以对照了。

## 1. 先装依赖

```powershell

go get github.com/golang-jwt/jwt/v5@latest
go get golang.org/x/crypto@latest
```

- `golang-jwt/jwt` —— 负责签发和校验登录 token
- `golang.org/x/crypto` —— 里面含 `bcrypt`，负责把密码变成不可逆的哈希

## 2. 三个概念，先讲清楚再写码

### 为什么密码不能存明文

数据库被拖走的话，明文密码等于把用户的账号送人。更严重的是，
很多人在不同网站用同一个密码，你泄露了会连累他们的邮箱、银行。

所以存的是 **bcrypt 哈希**：一个单向函数，能把 `123456` 变成
`$2a$10$N9qo8uLOickgx2ZMRZoMye...` 这种 60 个字符的串，
但**没法从这串反推回 `123456`**。登录时把用户输入的密码同样哈希一遍，比对结果是否一致。

**bcrypt 有个坑**：它只处理**前 72 字节**，超长的密码会被静默截断。
所以下面代码里把密码长度上限定在 72，避免出现「密码前半段对就能登录」这种情况。

### JWT 是什么

用户登录成功后，后端发一张「通行证」给他。之后每次请求带上这张证，
后端验证证是真的、没过期，就知道「你是谁」了。

JWT 长这样，用两个点分成三段：

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxIiwiZXhwIjoxNzU4MDk5MjAwfQ.4pcPyMD09olPSyXnrXCjTwXyr4BsezdI1AVTmud2fU4
   └── 头部：声明算法         └── 载荷：放用户ID和过期时间      └── 签名：防伪造
```

**关键点**：载荷只是 Base64 编码，**任何人都能解开看**，所以里面绝不能放密码之类的敏感信息。
安全全靠第三段签名——没有你的密钥，别人改一个字签名就对不上。

本项目的约定：**载荷里只放用户 ID，有效期 24 小时**。

### 为什么要加锁

Gin 给**每个请求开一个独立的 goroutine**（可以理解成轻量线程），
这些请求是真正同时在跑的。Go 的 map 并发写入会直接让进程崩溃：

```
fatal error: concurrent map writes
```

所以内存存储必须用 `sync.RWMutex` 加锁：写的时候独占（`Lock`），
读的时候可以并发（`RLock`）。第 4 节换成 MySQL 后就不需要了——
数据库自己处理并发。

## 3. 完整代码

把 `backend/main.go` **整个替换**成下面内容：

```go
package main

import (
	"errors"
	"log"
	"net/http"
	"os"
	"strconv"
	"strings"
	"sync"
	"time"

	"github.com/gin-gonic/gin"
	"github.com/golang-jwt/jwt/v5"
	"golang.org/x/crypto/bcrypt"
)

// ============================================================
// 1. 数据模型
// ============================================================

// User 是内存里的一条用户记录。
// Password 存的是 bcrypt 哈希不是明文；json:"-" 保证它永远不会被序列化给前端。
type User struct {
	ID        uint      `json:"id"`
	Username  string    `json:"username"`
	Password  string    `json:"-"`
	Nickname  string    `json:"nickname"`
	CreatedAt time.Time `json:"createdAt"`
}

// ============================================================
// 2. 内存存储（第 4 节会把这个换成 MySQL，接口保持不变）
// ============================================================

// userStore 用两个 map 假装是数据库。
// 必须加锁：多个请求同时写 map 会让进程直接崩溃。
type userStore struct {
	mu     sync.RWMutex
	nextID uint
	byID   map[uint]*User
	byName map[string]*User
}

func newUserStore() *userStore {
	return &userStore{
		nextID: 1,
		byID:   make(map[uint]*User),
		byName: make(map[string]*User),
	}
}

// Create 插入一个新用户。用户名重复时返回错误。
func (s *userStore) Create(username, hashedPassword, nickname string) (*User, error) {
	s.mu.Lock()
	defer s.mu.Unlock() // defer 保证函数返回前一定会解锁，即使中途 panic

	if _, exists := s.byName[username]; exists {
		return nil, errors.New("用户名已被占用")
	}

	user := &User{
		ID:        s.nextID,
		Username:  username,
		Password:  hashedPassword,
		Nickname:  nickname,
		CreatedAt: time.Now(),
	}
	s.nextID++
	s.byID[user.ID] = user
	s.byName[user.Username] = user

	return user, nil
}

func (s *userStore) FindByUsername(username string) (*User, bool) {
	s.mu.RLock()
	defer s.mu.RUnlock()
	user, ok := s.byName[username]
	return user, ok
}

func (s *userStore) FindByID(id uint) (*User, bool) {
	s.mu.RLock()
	defer s.mu.RUnlock()
	user, ok := s.byID[id]
	return user, ok
}

// ============================================================
// 3. JWT 签发与校验
// ============================================================

// contextUserIDKey 是往 gin.Context 里存用户 ID 用的键。
// 定义成常量防止手写字符串时拼错。
const contextUserIDKey = "userID"

// issueToken 签发一个 24 小时有效的 HS256 token，用户 ID 放在 Subject 里。
func issueToken(secret []byte, userID uint) (string, error) {
	now := time.Now()
	claims := jwt.RegisteredClaims{
		Subject:   strconv.FormatUint(uint64(userID), 10),
		Issuer:    "ganblog",
		IssuedAt:  jwt.NewNumericDate(now),
		ExpiresAt: jwt.NewNumericDate(now.Add(24 * time.Hour)),
	}
	return jwt.NewWithClaims(jwt.SigningMethodHS256, claims).SignedString(secret)
}

// requireAuth 是中间件：请求先过这里，验证通过才轮到业务处理函数。
func requireAuth(secret []byte) gin.HandlerFunc {
	return func(c *gin.Context) {
		const prefix = "Bearer "

		header := c.GetHeader("Authorization")
		if !strings.HasPrefix(header, prefix) {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{
				"error": "请在 Authorization 请求头里带上 Bearer <token>",
			})
			return
		}

		claims := &jwt.RegisteredClaims{}
		token, err := jwt.ParseWithClaims(
			strings.TrimPrefix(header, prefix),
			claims,
			// 第二个参数告诉库「用哪把钥匙验签」。密钥只有服务端有，别人伪造不出来。
			func(*jwt.Token) (any, error) { return secret, nil },
			// 只接受 HS256。不加这句的话，攻击者可以把头部改成 alg:none 来绕过验签。
			jwt.WithValidMethods([]string{jwt.SigningMethodHS256.Alg()}),
		)
		if err != nil || !token.Valid {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "登录状态已失效，请重新登录"})
			return
		}

		userID, err := strconv.ParseUint(claims.Subject, 10, 64)
		if err != nil {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "token 内容异常"})
			return
		}

		// 存进上下文，后续的业务处理函数用 c.Get 就能取到
		c.Set(contextUserIDKey, uint(userID))
		c.Next() // 交给下一个处理函数
	}
}

// ============================================================
// 4. 请求参数（用 binding 标签做校验，Gin 会自动执行）
// ============================================================

type registerRequest struct {
	Username string `json:"username" binding:"required,min=3,max=20"`
	Password string `json:"password" binding:"required,min=6,max=72"`
	Nickname string `json:"nickname" binding:"max=20"`
}

type loginRequest struct {
	Username string `json:"username" binding:"required"`
	Password string `json:"password" binding:"required"`
}

// ============================================================
// 5. 业务处理函数
// ============================================================

// handleRegister 处理 POST /api/users/register
func handleRegister(store *userStore) gin.HandlerFunc {
	return func(c *gin.Context) {
		var req registerRequest
		// ShouldBindJSON 把请求体的 JSON 解析进 req，并执行 binding 标签里的校验。
		// 校验不通过会返回 error，我们统一当 400 处理。
		if err := c.ShouldBindJSON(&req); err != nil {
			c.JSON(http.StatusBadRequest, gin.H{"error": "参数不合法：" + err.Error()})
			return
		}

		// 哈希密码。DefaultCost(=10) 是安全性和速度的平衡点，够用。
		hashed, err := bcrypt.GenerateFromPassword([]byte(req.Password), bcrypt.DefaultCost)
		if err != nil {
			c.JSON(http.StatusInternalServerError, gin.H{"error": "密码加密失败"})
			return
		}

		user, err := store.Create(req.Username, string(hashed), req.Nickname)
		if err != nil {
			c.JSON(http.StatusConflict, gin.H{"error": err.Error()})
			return
		}

		// user 里的 Password 字段有 json:"-"，不会被返回出去
		c.JSON(http.StatusCreated, gin.H{"data": user})
	}
}

// handleLogin 处理 POST /api/users/login
func handleLogin(store *userStore, secret []byte) gin.HandlerFunc {
	return func(c *gin.Context) {
		var req loginRequest
		if err := c.ShouldBindJSON(&req); err != nil {
			c.JSON(http.StatusBadRequest, gin.H{"error": "参数不合法：" + err.Error()})
			return
		}

		user, ok := store.FindByUsername(req.Username)
		if !ok {
			// 用户不存在和密码错误返回同一句话：不给攻击者探测「哪些用户名已被注册」的线索
			c.JSON(http.StatusUnauthorized, gin.H{"error": "用户名或密码错误"})
			return
		}

		if err := bcrypt.CompareHashAndPassword([]byte(user.Password), []byte(req.Password)); err != nil {
			c.JSON(http.StatusUnauthorized, gin.H{"error": "用户名或密码错误"})
			return
		}

		token, err := issueToken(secret, user.ID)
		if err != nil {
			c.JSON(http.StatusInternalServerError, gin.H{"error": "签发 token 失败"})
			return
		}

		c.JSON(http.StatusOK, gin.H{"data": gin.H{"token": token, "user": user}})
	}
}

// handleMe 处理 GET /api/users/me，返回当前登录用户
func handleMe(store *userStore) gin.HandlerFunc {
	return func(c *gin.Context) {
		// requireAuth 中间件保证走到这里时一定存过值，但仍要断言类型，
		// 因为 c.Get 返回的是 any（任意类型）。
		value, exists := c.Get(contextUserIDKey)
		if !exists {
			c.JSON(http.StatusUnauthorized, gin.H{"error": "未登录"})
			return
		}
		userID, ok := value.(uint)
		if !ok {
			c.JSON(http.StatusInternalServerError, gin.H{"error": "上下文中的用户 ID 类型异常"})
			return
		}

		user, ok := store.FindByID(userID)
		if !ok {
			c.JSON(http.StatusNotFound, gin.H{"error": "用户不存在"})
			return
		}

		c.JSON(http.StatusOK, gin.H{"data": user})
	}
}

// ============================================================
// 6. 入口
// ============================================================

func main() {
	// 密钥从环境变量读，读不到才用开发默认值。
	// 上线前必须设置 JWT_SECRET，否则别人能自己签发 token 冒充任意用户。
	secret := []byte(os.Getenv("JWT_SECRET"))
	if len(secret) == 0 {
		secret = []byte("dev-secret-change-me")
		log.Println("警告：未设置 JWT_SECRET，正在使用开发默认值，上线前必须改掉")
	}

	store := newUserStore()

	router := gin.Default()

	api := router.Group("/api")
	{
		api.GET("/health", func(c *gin.Context) {
			c.JSON(http.StatusOK, gin.H{"status": "ok"})
		})

		users := api.Group("/users")
		{
			users.POST("/register", handleRegister(store))
			users.POST("/login", handleLogin(store, secret))
			// 第三个参数是中间件：先过 requireAuth，通过了才执行 handleMe
			users.GET("/me", requireAuth(secret), handleMe(store))
		}
	}

	log.Println("服务已启动：http://localhost:8080")
	if err := router.Run(":8080"); err != nil {
		log.Fatal(err)
	}
}
```

> **注意 `router.Group` 的花括号 `{}`**：这只是给人看的，把同一个前缀的路由缩进在一起。
> Go 里它不是必须的语法，但这样组织读起来清楚。

## 5. 用 curl 走一遍完整流程

**这一步一定要做**，先用命令行确认后端是对的，再去接前端。
（Windows 的 `cmd` 对单引号支持不好，**用 PowerShell 或 Git Bash**。）

### ① 注册

```powershell
curl -X POST http://localhost:8080/api/users/register `
  -H "Content-Type: application/json" `
  -d '{\"username\":\"ganlh\",\"password\":\"123456\",\"nickname\":\"甘\"}'
```

返回 `201`：

```json
{"data":{"id":1,"username":"ganlh","nickname":"甘","createdAt":"2026-09-16T15:04:05.123+08:00"}}
```

**注意返回里没有 `password` 字段**——这是 `json:"-"` 起的作用。

### ② 重复注册同一个用户名

再执行一次上面的命令，返回 `409`：

```json
{"error":"用户名已被占用"}
```

### ③ 登录，拿 token

```powershell
curl -X POST http://localhost:8080/api/users/login `
  -H "Content-Type: application/json" `
  -d '{\"username\":\"ganlh\",\"password\":\"123456\"}'
```

返回 `200`，`token` 就是你之后要带着的通行证：

```json
{"data":{"token":"eyJhbGciOiJIUzI1NiIs...","user":{...}}}
```

### ④ 用 token 拿当前用户

把上一步的 token 复制进来：

```powershell
curl http://localhost:8080/api/users/me `
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."
```

返回 `200` 和你的用户信息。

### ⑤ 不带 token 试试

```powershell
curl http://localhost:8080/api/users/me
```

返回 `401`：

```json
{"error":"请在 Authorization 请求头里带上 Bearer <token>"}
```

**⑤ 能返回 401 很关键**——说明鉴权真的在生效。如果它返回了 200，说明中间件没接上。

## 6. 接口一览

前端对接就照这张表。

| 方法 | 路径 | 需要 token | 请求体 | 成功状态码 |
|------|------|-----------|--------|-----------|
| GET | `/api/health` | 否 | - | 200 |
| POST | `/api/users/register` | 否 | `{username, password, nickname}` | 201 |
| POST | `/api/users/login` | 否 | `{username, password}` | 200 |
| GET | `/api/users/me` | **是** | - | 200 |

**统一的响应格式**（前端可以照这个写通用处理）：

- 成功：`{"data": ...}`
- 失败：`{"error": "人话描述"}`

需要 token 的接口，在请求头里加：`Authorization: Bearer <token>`。

## 7. 这一版的已知短板

心里有数就好，第 4、5 节解决：

- **数据存在内存里**，重启就没了 → 第 4 节换 MySQL
- **没法分页查用户列表**，也没有改昵称、改密码 → 第 5 节加
- **token 没法主动作废**，改密码后旧 token 在 24 小时内仍然有效 → 后面可以引入黑名单或改用短 token + refresh token
- **全在一个文件里**，再加「文章」就会乱成一团 → 第 5 节拆分层
