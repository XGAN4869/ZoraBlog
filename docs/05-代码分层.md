# 05 · 代码分层

现在 `main.go` 有四百多行，什么都塞在一起。再加「文章」「评论」模块会彻底乱掉。

这一节把它拆成**能长大的结构**。**功能一行不变**，纯粹搬家 + 加一层。

## 1. 拆成什么样

```
backend/
├── go.mod
├── go.sum
├── Dockerfile
├── .dockerignore
├── main.go                      ← 只剩「装配 + 启动」，约 40 行
└── internal/
    ├── config/
    │   └── config.go            ← 配置：端口、DSN、密钥
    ├── database/
    │   └── mysql.go             ← 连 MySQL、建表
    ├── model/
    │   └── user.go              ← 数据结构 = 数据库表
    ├── store/
    │   └── user.go              ← 只管读写数据库
    ├── service/
    │   └── user.go              ← 业务规则：密码怎么加密、谁能登录
    ├── handler/
    │   └── user.go              ← 只管 HTTP：解析请求、拼响应
    ├── middleware/
    │   └── auth.go              ← JWT 鉴权中间件
    └── router/
        └── router.go            ← 路由表
```

### 为什么要 `internal/`

这是 Go 的**硬性约定**（编译器强制）：`internal` 目录下的包，
**只能被同一个模块内的代码 import**。

人话：给代码盖上「私有」章，防止以后你把项目开源时，别人直接 import 你的内部实现，
那时候你想重构都动不了（一动就破坏别人的代码）。

### 箭头只能这么走

```
main → router → handler → service → store → model
                    ↓
                middleware
```

**关键规则：依赖只能单向向下，不能反向，也不能跳。**

- `store` **不能** import `service` —— 数据库层不认识业务规则
- `handler` **不能**直接 import `store` —— 必须经过 `service`
- `model` **不能** import 任何内部包 —— 它是纯数据定义

为什么非要这样？**因为「文章」模块马上要来了。** 加文章的时候，
`router` 加一组路由、`handler/post.go` / `service/post.go` / `store/post.go` / `model/post.go` 各加一个文件，
`user` 相关的一行都不用改。如果全揉在一起，加文章就会牵一发动全身。

### 每一层到底该写什么

| 层 | 只做这些 | **不该**做这些 |
|----|---------|--------------|
| `handler` | 解析请求、校验参数格式、把错误翻译成状态码 | 写 SQL、算业务规则 |
| `service` | 业务规则、多个 store 的编排、事务 | 碰 `gin.Context`、写 SQL |
| `store` | 增删改查、把数据库错误翻译成本包错误 | 判断「密码对不对」这种业务逻辑 |
| `model` | 定义字段和标签 | 任何函数逻辑 |

一条好记的判断标准：**`service` 层如果 import 了 `gin`，就是分层错了。**
业务规则不该知道 HTTP 的存在——这样以后写命令行工具、定时任务都能复用 service。

### `internal/config/config.go`

```go
package config

import "os"

// Config 汇总所有配置项。以后加配置就在这里加字段 + 在 Load 里给默认值。
type Config struct {
	Port      string
	DSN       string
	JWTSecret string
}

// Load 从环境变量读配置，读不到就用默认值。
// 默认值面向本地开发；上线时用环境变量覆盖，不需要改代码。
func Load() Config {
	return Config{
		Port: getEnv("PORT", "8080"),
		DSN: getEnv("DB_DSN",
			"ganblog:ganblogpass@tcp(127.0.0.1:3306)/ganblog?charset=utf8mb4&parseTime=True&loc=Local"),
		JWTSecret: getEnv("JWT_SECRET", "dev-secret-change-me"),
	}
}

func getEnv(key, fallback string) string {
	if value := os.Getenv(key); value != "" {
		return value
	}
	return fallback
}
```

> **为什么要集中管理配置**：默认值散落在代码各处的话，上线前你得满仓库找「哪几个值要改」。
> 集中一处，看一个文件就够了。

package model

import "time"

// User 对应数据库里的 users 表。GORM 默认把 User 映射成表名 users。
type User struct {
	ID       uint   `gorm:"primaryKey" json:"id"`
	Username string `gorm:"size:32;uniqueIndex;not null" json:"username"`
	// bcrypt 哈希固定 60 字符，size:100 留余量。
	// json:"-" 保证这个字段不会被序列化给前端。
	Password string `gorm:"size:100;not null" json:"-"`
	Nickname string `gorm:"size:32" json:"nickname"`
	// 这两个是 GORM 的约定字段名，插入/更新时自动写入
	CreatedAt time.Time `json:"createdAt"`
	UpdatedAt time.Time `json:"updatedAt"`
}

### `internal/database/mysql.go`

```go
package database

import (
	"fmt"
	"time"

	"ganblog/internal/model"

	"gorm.io/driver/mysql"
	"gorm.io/gorm"
	"gorm.io/gorm/logger"
)

// Connect 建立数据库连接，并按长期运行的服务调好连接池。
func Connect(dsn string) (*gorm.DB, error) {
	db, err := gorm.Open(mysql.Open(dsn), &gorm.Config{
		// 把驱动的原始错误翻译成 GORM 的通用错误，
		// 这样 store 层能直接用 errors.Is(err, gorm.ErrDuplicatedKey) 判断唯一键冲突，
		// 不用去认 MySQL 的错误码 1062。
		TranslateError: true,
		// Warn 级别只打印慢查询和错误，避免每条 SQL 都刷屏
		Logger: logger.Default.LogMode(logger.Warn),
	})
	if err != nil {
		return nil, fmt.Errorf("连接 MySQL 失败：%w", err)
	}

	sqlDB, err := db.DB()
	if err != nil {
		return nil, fmt.Errorf("获取底层连接池失败：%w", err)
	}

	// 不设上限的话，并发一高就会把数据库的连接数吃光
	sqlDB.SetMaxOpenConns(25)
	sqlDB.SetMaxIdleConns(5)
	sqlDB.SetConnMaxLifetime(time.Hour)

	return db, nil
}

// Migrate 根据 model 定义自动建表 / 补字段。
// 开发期很方便，正式环境建议改用 SQL 迁移文件——AutoMigrate 只会加不会删，
// 而且改字段类型时行为不直观，生产上不好控制。
func Migrate(db *gorm.DB) error {
	return db.AutoMigrate(&model.User{})
}
```

### `internal/store/user.go`

```go
package store

import (
	"errors"

	"ganblog/internal/model"

	"gorm.io/gorm"
)

// 本包对外的错误约定。上层用 errors.Is 判断，
// 不去关心底层到底是 MySQL、Postgres 还是内存。
var (
	ErrNotFound  = errors.New("记录不存在")
	ErrDuplicate = errors.New("记录已存在")
)

type UserStore struct {
	db *gorm.DB
}

func NewUserStore(db *gorm.DB) *UserStore {
	return &UserStore{db: db}
}

// Create 插入新用户。用户名冲突时返回 ErrDuplicate。
// 插入成功后 GORM 会把自增 ID 和 CreatedAt/UpdatedAt 回填进 user。
func (s *UserStore) Create(user *model.User) error {
	err := s.db.Create(user).Error
	if errors.Is(err, gorm.ErrDuplicatedKey) {
		return ErrDuplicate
	}
	return err
}

// FindByUsername 按用户名查。
// 注意 ? 占位符：绝不能把变量拼进 SQL 字符串，否则用户输入
// ' OR '1'='1 就能绕过校验（SQL 注入）。? 由驱动负责转义。
func (s *UserStore) FindByUsername(username string) (*model.User, error) {
	var user model.User
	if err := s.db.Where("username = ?", username).First(&user).Error; err != nil {
		return nil, translate(err)
	}
	return &user, nil
}

// FindByID 按主键查。
func (s *UserStore) FindByID(id uint) (*model.User, error) {
	var user model.User
	if err := s.db.First(&user, id).Error; err != nil {
		return nil, translate(err)
	}
	return &user, nil
}

// UpdateNickname 改昵称。RowsAffected 为 0 说明这个 ID 不存在。
func (s *UserStore) UpdateNickname(id uint, nickname string) error {
	result := s.db.Model(&model.User{}).Where("id = ?", id).Update("nickname", nickname)
	if result.Error != nil {
		return result.Error
	}
	if result.RowsAffected == 0 {
		return ErrNotFound
	}
	return nil
}

// translate 把 GORM 的「没查到」翻译成本包的 ErrNotFound。
func translate(err error) error {
	if errors.Is(err, gorm.ErrRecordNotFound) {
		return ErrNotFound
	}
	return err
}
```

> **`translate` 存在的意义**：如果没有它，`service` 层就必须 `import gorm` 才能判断「没查到」，
> 那以后想换数据库就得到处改。现在 `service` 只认 `store.ErrNotFound`，换底层时它一行不用动。

### `internal/service/user.go`

```go
package service

import (
	"errors"
	"fmt"
	"strconv"
	"time"

	"ganblog/internal/model"
	"ganblog/internal/store"

	"github.com/golang-jwt/jwt/v5"
	"golang.org/x/crypto/bcrypt"
)

// 本包对外的业务错误。handler 层根据它们决定返回哪个 HTTP 状态码。
var (
	ErrUsernameTaken = errors.New("用户名已被占用")
	ErrInvalidLogin  = errors.New("用户名或密码错误")
	ErrUserNotFound  = errors.New("用户不存在")
)

type UserService struct {
	users  *store.UserStore
	secret []byte
}

func NewUserService(users *store.UserStore, secret []byte) *UserService {
	return &UserService{users: users, secret: secret}
}

// Register 加密密码并创建用户。
func (s *UserService) Register(username, password, nickname string) (*model.User, error) {
	// Go 的哈希函数返回 []byte，存进数据库前要转成 string
	hashed, err := bcrypt.GenerateFromPassword([]byte(password), bcrypt.DefaultCost)
	if err != nil {
		return nil, fmt.Errorf("密码加密失败：%w", err)
	}

	user := &model.User{
		Username: username,
		Password: string(hashed),
		Nickname: nickname,
	}
	if err := s.users.Create(user); err != nil {
		if errors.Is(err, store.ErrDuplicate) {
			return nil, ErrUsernameTaken
		}
		return nil, err
	}

	return user, nil
}

// Login 校验账号密码，成功返回签好的 token 和用户信息。
func (s *UserService) Login(username, password string) (string, *model.User, error) {
	user, err := s.users.FindByUsername(username)
	if err != nil {
		if errors.Is(err, store.ErrNotFound) {
			// 用户不存在和密码错误返回同一个错误，
			// 不给攻击者探测「这个用户名是否已注册」的线索
			return "", nil, ErrInvalidLogin
		}
		return "", nil, err
	}

	if err := bcrypt.CompareHashAndPassword([]byte(user.Password), []byte(password)); err != nil {
		return "", nil, ErrInvalidLogin
	}

	token, err := s.issueToken(user.ID)
	if err != nil {
		return "", nil, err
	}

	return token, user, nil
}

// GetByID 查询用户，供「获取当前登录用户」使用。
func (s *UserService) GetByID(id uint) (*model.User, error) {
	user, err := s.users.FindByID(id)
	if err != nil {
		if errors.Is(err, store.ErrNotFound) {
			return nil, ErrUserNotFound
		}
		return nil, err
	}
	return user, nil
}

// issueToken 签发 24 小时有效的 HS256 token，用户 ID 放在 Subject 里。
// 小写开头 = 包内私有，外面调不到。
func (s *UserService) issueToken(userID uint) (string, error) {
	now := time.Now()
	claims := jwt.RegisteredClaims{
		Subject:   strconv.FormatUint(uint64(userID), 10),
		Issuer:    "ganblog",
		IssuedAt:  jwt.NewNumericDate(now),
		ExpiresAt: jwt.NewNumericDate(now.Add(24 * time.Hour)),
	}
	return jwt.NewWithClaims(jwt.SigningMethodHS256, claims).SignedString(s.secret)
}
```

> **Go 的大小写规则**：首字母**大写** = 其他包能访问（`public`）；
> 首字母**小写** = 只有本包内能访问（`private`）。
> Go 没有 `public` / `private` 关键字，全靠大小写。所以 `issueToken` 外面调不到，是对的。

### `internal/handler/user.go`

```go
package handler

import (
	"errors"
	"net/http"

	"ganblog/internal/middleware"
	"ganblog/internal/service"

	"github.com/gin-gonic/gin"
)

type UserHandler struct {
	svc *service.UserService
}

func NewUserHandler(svc *service.UserService) *UserHandler {
	return &UserHandler{svc: svc}
}

// 请求参数用结构体的 binding 标签做格式校验，Gin 会自动执行
type registerRequest struct {
	Username string `json:"username" binding:"required,min=3,max=20"`
	Password string `json:"password" binding:"required,min=6,max=72"`
	Nickname string `json:"nickname" binding:"max=20"`
}

type loginRequest struct {
	Username string `json:"username" binding:"required"`
	Password string `json:"password" binding:"required"`
}

// Register 处理 POST /api/users/register
func (h *UserHandler) Register(c *gin.Context) {
	var req registerRequest
	if err := c.ShouldBindJSON(&req); err != nil {
		c.JSON(http.StatusBadRequest, gin.H{"error": "参数不合法：" + err.Error()})
		return
	}

	user, err := h.svc.Register(req.Username, req.Password, req.Nickname)
	// 用 switch 把 service 的业务错误映射成 HTTP 状态码，
	// 这个映射只应该出现在 handler 层
	switch {
	case errors.Is(err, service.ErrUsernameTaken):
		c.JSON(http.StatusConflict, gin.H{"error": err.Error()})
	case err != nil:
		// c.Error 会被 gin.Default() 里的 Logger 中间件打印到控制台。
		// 真实错误给开发看，返回给前端的话越模糊越安全（避免泄露内部结构）。
		c.Error(err)
		c.JSON(http.StatusInternalServerError, gin.H{"error": "注册失败，请稍后重试"})
	default:
		c.JSON(http.StatusCreated, gin.H{"data": user})
	}
}

// Login 处理 POST /api/users/login
func (h *UserHandler) Login(c *gin.Context) {
	var req loginRequest
	if err := c.ShouldBindJSON(&req); err != nil {
		c.JSON(http.StatusBadRequest, gin.H{"error": "参数不合法：" + err.Error()})
		return
	}

	token, user, err := h.svc.Login(req.Username, req.Password)
	switch {
	case errors.Is(err, service.ErrInvalidLogin):
		c.JSON(http.StatusUnauthorized, gin.H{"error": err.Error()})
	case err != nil:
		c.Error(err)
		c.JSON(http.StatusInternalServerError, gin.H{"error": "登录失败，请稍后重试"})
	default:
		c.JSON(http.StatusOK, gin.H{"data": gin.H{"token": token, "user": user}})
	}
}

// Me 处理 GET /api/users/me，必须先过 RequireAuth 中间件
func (h *UserHandler) Me(c *gin.Context) {
	value, exists := c.Get(middleware.UserIDKey)
	if !exists {
		c.JSON(http.StatusUnauthorized, gin.H{"error": "未登录"})
		return
	}
	// c.Get 返回 any，必须断言成具体类型才能用
	userID, ok := value.(uint)
	if !ok {
		c.Error(errors.New("context 里的 userID 类型异常"))
		c.JSON(http.StatusInternalServerError, gin.H{"error": "服务器内部错误"})
		return
	}

	user, err := h.svc.GetByID(userID)
	switch {
	case errors.Is(err, service.ErrUserNotFound):
		c.JSON(http.StatusNotFound, gin.H{"error": err.Error()})
	case err != nil:
		c.Error(err)
		c.JSON(http.StatusInternalServerError, gin.H{"error": "查询失败，请稍后重试"})
	default:
		c.JSON(http.StatusOK, gin.H{"data": user})
	}
}
```

### `internal/middleware/auth.go`

```go
package middleware

import (
	"net/http"
	"strconv"
	"strings"

	"github.com/gin-gonic/gin"
	"github.com/golang-jwt/jwt/v5"
)

// UserIDKey 是往 gin.Context 里存用户 ID 用的键。
// 导出成常量，handler 用 middleware.UserIDKey 取值，避免手写字符串拼错。
const UserIDKey = "userID"

// RequireAuth 校验 Authorization 头里的 JWT。通过则把用户 ID 存进上下文。
func RequireAuth(secret []byte) gin.HandlerFunc {
	return func(c *gin.Context) {
		const prefix = "Bearer "

		header := c.GetHeader("Authorization")
		if !strings.HasPrefix(header, prefix) {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{
				"error": "请在 Authorization 请求头里带上 Bearer <token>",
			})
			return
		}

		claims := &jwt.RegisteredClaims{}
		token, err := jwt.ParseWithClaims(
			strings.TrimPrefix(header, prefix),
			claims,
			// 用服务端密钥验签。密钥只有服务端有，别人伪造不出合法 token。
			func(*jwt.Token) (any, error) { return secret, nil },
			// 只接受 HS256。不加这句的话，攻击者可以把头部改成 alg:none 绕过验签。
			jwt.WithValidMethods([]string{jwt.SigningMethodHS256.Alg()}),
		)
		if err != nil || !token.Valid {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "登录状态已失效，请重新登录"})
			return
		}

		userID, err := strconv.ParseUint(claims.Subject, 10, 64)
		if err != nil {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "token 内容异常"})
			return
		}

		c.Set(UserIDKey, uint(userID))
		c.Next() // 交给下一个处理函数
	}
}
```

> **`AbortWithStatusJSON` 和 `JSON` 的区别**：前者会同时**中止**后续处理函数，
> 后者只是写响应然后继续往下走。鉴权失败必须用 `Abort`，否则请求会继续跑到业务代码里去。

### `internal/router/router.go`

```go
package router

import (
	"net/http"

	"ganblog/internal/handler"
	"ganblog/internal/middleware"

	"github.com/gin-gonic/gin"
)

// Dependencies 是 router 需要的所有东西，由 main.go 装配好传进来。
// 以后加文章、评论模块，就在这里加字段。
type Dependencies struct {
	UserHandler *handler.UserHandler
	JWTSecret   []byte
}

// New 注册所有路由。加新模块就在 api 下面加一组。
func New(deps Dependencies) *gin.Engine {
	r := gin.Default()

	api := r.Group("/api")
	{
		api.GET("/health", func(c *gin.Context) {
			c.JSON(http.StatusOK, gin.H{"status": "ok"})
		})

		users := api.Group("/users")
		{
			users.POST("/register", deps.UserHandler.Register)
			users.POST("/login", deps.UserHandler.Login)

			// 空字符串 + 中间件 = 在同一个 /api/users 前缀下再开一组，
			// 这组里的路由都要先通过鉴权。以后发文章、改资料都挂这里。
			auth := users.Group("", middleware.RequireAuth(deps.JWTSecret))
			{
				auth.GET("/me", deps.UserHandler.Me)
			}
		}
	}

	return r
}
```

### `main.go`

把原来四百多行的内容**全部删掉**，换成：

```go
package main

import (
	"log"

	"ganblog/internal/config"
	"ganblog/internal/database"
	"ganblog/internal/handler"
	"ganblog/internal/router"
	"ganblog/internal/service"
	"ganblog/internal/store"
)

func main() {
	// 1. 读配置
	cfg := config.Load()

	// 2. 连数据库 + 建表
	db, err := database.Connect(cfg.DSN)
	if err != nil {
		log.Fatalf("数据库连接失败：%v", err)
	}
	if err := database.Migrate(db); err != nil {
		log.Fatalf("建表失败：%v", err)
	}
	log.Println("数据库连接成功，表结构已同步")

	// 3. 自下而上装配：store → service → handler
	//    谁依赖谁一目了然，这就是分层最大的好处
	userStore := store.NewUserStore(db)
	userService := service.NewUserService(userStore, []byte(cfg.JWTSecret))
	userHandler := handler.NewUserHandler(userService)

	// 4. 注册路由
	r := router.New(router.Dependencies{
		UserHandler: userHandler,
		JWTSecret:   []byte(cfg.JWTSecret),
	})

	// 5. 启动
	log.Printf("服务已启动：http://localhost:%s", cfg.Port)
	if err := r.Run(":" + cfg.Port); err != nil {
		log.Fatalf("服务启动失败：%v", err)
	}
}
```

## 3. 验证重构没改坏东西

拆完必须**重跑一遍完整流程**。重构最容易出「看起来没问题但悄悄坏了」的事。

```powershell
go mod tidy
go vet ./...
go run .
```

然后依次测：

```powershell
# 注册（换个没注册过的用户名）
curl -X POST http://localhost:8080/api/users/register -H "Content-Type: application/json" -d '{\"username\":\"tester\",\"password\":\"123456\"}'

# 登录
curl -X POST http://localhost:8080/api/users/login -H "Content-Type: application/json" -d '{\"username\":\"tester\",\"password\":\"123456\"}'

# 用上一步返回的 token 查当前用户
curl http://localhost:8080/api/users/me -H "Authorization: Bearer <粘这里>"

# 不带 token，应该 401
curl http://localhost:8080/api/users/me
```

**结果和上一节完全一致才算重构成功。**

## 4. 下一步加「文章」模块要动哪些文件

这就是分层的意义。加文章功能，**只新增文件，不改已有的**：

| 文件 | 动作 |
|------|------|
| `internal/model/post.go` | 新增 |
| `internal/store/post.go` | 新增 |
| `internal/service/post.go` | 新增 |
| `internal/handler/post.go` | 新增 |
| `internal/router/router.go` | **改**：加一组 `/api/posts` 路由 |
| `main.go` | **改**：装配 post 的三层 |
| `internal/database/mysql.go` | **改**：`AutoMigrate` 里加上 `&model.Post{}` |

`user` 相关的文件**一个都不用碰**。对照一下：如果代码还是揉在 `main.go` 里，
加文章就得在一个几百行的文件里小心翼翼地插入，改错一行可能连登录都坏了。
